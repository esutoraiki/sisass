Estructura del proyecto

Tipo: Artículo

Versión: 2.x.x

Este artículo explica cómo se divide el repositorio de SISASS y dónde debes trabajar según el tipo de cambio. El proyecto separa el código fuente del framework, la carga core que usa el instalador y el sitio de documentación.

src es la fuente editable del framework. En esta carpeta se corrige o amplía el comportamiento real de los mixins, funciones y módulos SCSS que mantiene SISASS.

files/ es la carga que install.js entrega al proyecto consumidor durante la instalación. Esta carga no se genera automáticamente desde src; se mantiene como un conjunto de archivos distribuibles. Por eso, si una mejora de la fuente también debe llegar a quien instala SISASS, el cambio correspondiente debe aplicarse en el activo distribuible.

docs/ es el sitio de documentación. Sus estilos pueden usar módulos de src al compilar, por lo que la documentación puede reflejar cambios de la fuente sin que eso signifique que la carga distribuible ya fue actualizada.

Mapa principal del repositorio

Ruta Responsabilidad Cuándo revisarla
src/ Fuente de los módulos SCSS del framework. Cuando modificas mixins, funciones o módulos de SISASS.
files/ Carga de archivos que utiliza el instalador. Cuando preparas o ajustas lo que se copia a un proyecto consumidor.
install.js Copia los activos y aplica las variantes de instalación. Cuando cambia el destino, el contenido instalado o el comportamiento de --dep.
arg.js Convierte los argumentos de la línea de comandos en opciones del instalador. Cuando agregas o modificas opciones como --path o --dep.
instances.config.js Define los módulos que se escriben en _instances.scss durante la instalación sqhtml2. Solo cuando cambia esa integración específica.
package.json y README.md Metadatos, comandos de npm, instalación y guía de uso del paquete. Cuando cambia la publicación, la instalación o la forma de consumir SISASS.
docs/ Sitio de documentación y recursos para presentar el proyecto. Cuando cambia una explicación, una página o la interfaz documental.
spec/ Especificaciones para cambios concretos. Cuando una tarea tiene criterios funcionales que deben cumplirse.

Fuente del framework: src

Ruta Qué contiene Relación con el framework
src/_sisass.scss Punto de entrada de las utilidades core exportadas. Reexporta _vendor.scss, _base.scss y _mediaqueries.scss; no reexporta reset, componentes, efectos ni formas.
src/_base.scss Mixins y funciones de uso general. Incluye utilidades para tipografía, layout, fondos, unidades, mapas, color, cadenas y listas.
src/_vendor.scss Mixins de compatibilidad y prefijos. Proporciona utilidades para propiedades que necesitan tratamiento vendor.
src/_mediaqueries.scss Mixins para breakpoints, altura y orientación. Construye las media queries usadas por las utilidades responsive.
src/_reset.scss Reset global de elementos HTML. Es un módulo independiente; no forma parte de los @forward de _sisass.scss.
src/components/ Componentes reutilizables como botones, carrusel y modal. Son parciales independientes y no se reexportan desde _sisass.scss.
src/effects/ Efectos visuales, animaciones y keyframes. Contiene parciales independientes para efectos de presentación.
src/shapes/ Formas geométricas reutilizables. Contiene parciales independientes como _triangles.scss.

No existe un archivo de variables en src/. Las variables distribuidas están en files/assets/scss/core/_variables.scss y la documentación define sus propias variables en docs/assets/scss/core/_variables.scss. La entrada _sisass.scss no representa todo el árbol de src: los componentes, efectos, formas y el reset se mantienen como módulos separados. Revisa el archivo que contiene la utilidad que vas a cambiar antes de editar el punto de entrada.

Activos de instalación: files/

La ruta files/assets/scss/core/ es la carga core que el instalador utiliza en algunos modos. Actualmente contiene variables y archivos base de integración; no contiene una copia completa de los módulos de src.

Archivo Estado y propósito actual
files/assets/scss/core/_variables.scss Contiene valores base para colores, tipografía, ruta de iconos, breakpoints y tiempos.
files/assets/scss/core/_fonts.scss Contiene una plantilla comentada para declarar fuentes; el modo sqhtml reemplaza esa plantilla por declaraciones de Roboto.
files/assets/scss/core/_mixin.scss Es un archivo base para mixins distribuidos y actualmente funciona como placeholder.
files/assets/scss/core/_keyframes.scss Es un archivo base para keyframes distribuidos y actualmente funciona como placeholder.
files/assets/scss/core/_instances.scss Es un placeholder en la carga normal; sqhtml2 lo genera de nuevo usando instances.config.js.
files/assets/scss/core/_layout.scss Usa instances y sirve como punto de conexión para la composición distribuida.

La distribución actual instala únicamente esta carga core. No instala sisass.scss, reset.scss, ni los directorios components/, effects/ o shapes/ de src. Por tanto, no debes asumir que la instalación estándar entrega por sí sola todos los módulos disponibles en el repositorio.

Relaciones estructurales reales

Origen Destino Relación
src/_sisass.scss docs/assets/scss/core/_instances.scss La documentación reexporta las utilidades core de SISASS para usarlas en sus estilos.
src/_reset.scss docs/assets/scss/core/_reset.scss El reset del sitio de documentación reenvía el reset fuente del framework.
docs/assets/scss/main.scss docs/assets/css/ El flujo de Gulp compila los estilos del sitio usando los módulos core y los estilos propios de documentación.
files/assets/scss/core/ Proyecto consumidor install.js copia esta carga core; no la reconstruye automáticamente desde src.
instances.config.js _instances.scss del destino sqhtml2 Define las sentencias @forward que se generan para módulos que deben existir en el proyecto consumidor.

Cómo funciona la instalación

Modo Origen Destino o efecto
Instalación normal files/ Copia la carga incluida en files/ al directorio raíz del proyecto consumidor; por defecto crea assets/.
--path files/assets/ Copia los activos dentro de la ruta indicada, por ejemplo resources/core/.
--dep sqhtml La misma carga que la instalación normal o --path. Después de copiar, ajusta _variables.scss y _fonts.scss para SQHTML.
--dep sqhtml2 files/assets/scss/core/ Ignora --path, copia directamente en ../../src/core/, aplica los ajustes de SQHTML y genera _instances.scss.

En una instalación personalizada, --path cambia la raíz de los recursos, no la fuente del framework. En cambio, sqhtml2 es una integración especial que fuerza su propio destino y genera referencias a módulos del proyecto consumidor; por eso no debe interpretarse como el flujo general de SISASS.

Dónde trabajar según el cambio

Necesidad Ubicación inicial Resultado esperado
Cambiar el comportamiento de un mixin o una función. src/ Actualizas la fuente del framework; revisa la documentación porque sus estilos importan módulos desde esta ruta.
Cambiar lo que instala el paquete. files/assets/scss/core/ e install.js Actualizas manualmente el activo distribuible y su proceso de copia.
Cambiar la integración con SQHTML. install.js y, si aplica, instances.config.js Modificas la rama correspondiente de --dep.
Corregir una explicación o una página del sitio. docs/ Modificas la documentación sin alterar la fuente ni la distribución del framework; su compilación sí depende de src.
Implementar una tarea con criterios específicos. spec/ Consultas y verificas la especificación asociada.

Regla práctica: modifica src para el framework, files/ para la carga core que se distribuye, install.js para el flujo de instalación y docs/ para explicar y compilar el sitio documental. No asumas que una carpeta se sincroniza automáticamente con otra ni que la carga instalada contiene todo el árbol fuente.
